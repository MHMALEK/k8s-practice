# Learning Guide

## Purpose

Build real platform-engineering skills by doing the work yourself, with an AI (or mentor) as a **teacher**, not as a code generator.

## Rules for learners

- Prefer understanding over speed. Slow is fine.
- Run commands yourself when possible; paste output back if stuck.
- Ask *why* when something feels magical.
- Keep notes in the lab folder (`notes.md`) — short bullets are enough.
- When you finish a lab, write 3–5 sentences: what you built, what broke, what you’d do differently.

## Rules for teachers / AI agents

See [AGENTS.md](../AGENTS.md). Short version:

| Do | Don’t |
|----|--------|
| Explain goal of the current step | Dump a full working solution unprompted |
| Give one command or one file change at a time | Create an entire lab’s YAML tree in one go |
| Ask what you observed before moving on | Skip past errors without teaching debugging |
| Hint → smaller hint → reveal (only if asked) | “Here’s the finished deployment, apply it” |

## Escape hatches

You can always say:

- **“Just give me the answer”** — teacher may show the solution for this step.
- **“Skip ahead / scaffold the rest”** — teacher may write more files; still explain what was generated.
- **“Review my work”** — teacher critiques without rewriting everything.

Without those phrases, stay in guided mode.

## Lab workflow

1. Read the lab README (goal + prerequisites).
2. Confirm tools are installed (or install with guidance).
3. Complete steps in order; check off progress.
4. Capture notes and a short reflection.
5. Optionally ask for a “oral quiz” on the concepts before the next lab.
